# ADR-0012: Goal-Registry Persistence (Sqlite Backing)

**Status**: Accepted (LOCKED, 2026-08-26) — rationale and rejected alternatives inline in this ADR (decisions **D-29..D-36**).

**Numbering note**: written against the merged tree at `docs/adr/` = 0001..0010, in-tree decision high-water mark **D-23** (ADR-0010). Queue state at write time: #95 owns D-24..D-26 in ADR-0009 (unmerged PR #105) and #96 owns D-27..D-28 in ADR-0011 (unmerged PR #108, renumbered at coordinating level, commit d604675) — neither ADR-0011 nor D-24..D-28 exist in this tree. This ADR's decisions are numbered first-free from **D-29**; the D-24..D-28 gap stays unfilled by design (those IDs belong to the queued slicers and are never re-used here).

## Context

Issue #97 asks what goal-registry state replay-from-events already reconstructs versus what is lost on restart, and — if a gap exists — to add sqlite backing behind `GoalRegistry` following `packages/server/src/persistence/` conventions, keeping the replay reducer as the source of truth and the DB as accelerator/cache. The binding acceptance criteria: (AC-1) replay-from-events and sqlite-backed state agree on the same committed log (parity test); (AC-2) a restart of a mid-run simulation resumes goals/verdicts/gap history.

The scope answer came from the code itself. `GoalRegistry.rebuildFromLog` (goal-registry.ts:41-89) reconstructs all five committed shapes from the log: proposals (`goal_proposed`/`goal_declined`, :53-72), goals (`goal_accepted`, :57-65), verdicts (`world_verdict`, last-writer-wins, :73-76), gapHistory (`delusion_gap_sampled`, same-`at` replacement plus the 32-sample replay cap, :78-82), and pendingOffer (`ending_offered`, first-wins, :84-89). The **only** state lost on restart is **selfVerdicts** — the LLM/non-committed self-verdict junction (goal-registry.ts:23: "never rebuilt from log"), proven by goal-registry.test.ts:238-270, which documents that a restart degrades to structural V1 verdicts. Five of the six registry shapes are therefore log-derived by construction; persisting them would write rows with zero runtime consumers (D-29).

Pre-existing surfaces this slice touches: **D-4** locked the registry store as "in-memory `GoalRegistry` + pure replay reducer … no repository interface, no sqlite", explicitly noting cross-restart durability was not a requirement *for that slice* (ADR-0009 decision 1, D-4 rationale) — this issue changes that requirement; **D-1** rejected a separate `IGoalRepository` interface with the `IMemoryRepository`-unwired norm (ADR-0009); **D-23** recorded the restart-degradation-to-structural-V1 consequence (ADR-0010) and its rejected alternatives (committing self-verdict events grows the event contract with no consumer; client-side memoization couples lifecycle). ADR-0011 does not exist on this tree (unmerged #96 branch, PR #108).

Positionality invariant carried in: snapshot windows are positional on log append order (ADR-0009 D-2). Both the in-memory store and the sqlite `events` read honor the same `IEventRepository` contract (`created_at ASC, id ASC` ordering), but a DB read feeding log-ordered state would be a positionality risk even so — the parity test feeds both builders from one committed list, and no sqlite read ever feeds log-ordered state at runtime (D-30).

## Decision

**1. Sqlite persists ONLY the non-replayable junction (D-29).** New table `goal_self_verdicts`, keyed `(simulation_id, goal_id)`: `simulation_id TEXT NOT NULL REFERENCES simulations(id) ON DELETE CASCADE`, `goal_id TEXT NOT NULL`, `verdict TEXT NOT NULL` (JSON `SelfVerdict`), `source TEXT NOT NULL` (`"llm" | "deterministic"`), `updated_at INTEGER NOT NULL`, `PRIMARY KEY (simulation_id, goal_id)` — snake_case + JSON-text + cascade per the house style (schema.ts `CREATE TABLE IF NOT EXISTS`, no migration versioning). The five committed shapes stay log-derived; DB rows for them would have zero runtime consumers.

**2. Replay stays the authority; the DB is a write-through cache (D-30).** Startup is `new GoalRegistry(log)` plus an overlay of stored selfVerdicts through the existing `recordSelfVerdict` junction API (restore loop filters stale rows via `registry.getGoal`, keyed overlay by goalId — last-writer-wins matches registry semantics). The DB's **only** read is the junction restore in `buildGoalLayerRuntime`; no sqlite read ever feeds log-ordered state, so the D-2 positionality invariant holds by construction. R-1 ("replay = source of truth, DB = accelerator/cache, never authority") is satisfied verbatim.

**3. Whole-junction write-through at review end, contained (D-31).** `WorldEvaluator.persistRegistryState(simulationId)` serializes `registry.getGoals()` → non-undefined `getSelfVerdict(goal.id)` and calls `saveSelfVerdicts` (per-row upsert, `INSERT … ON CONFLICT(simulation_id, goal_id) DO UPDATE`). `PulseScheduler` calls it immediately after `appendAndProject` commits, **after** the operatorEvents loop — so on every review, including candidate-less and zero-commit reviews (the LLM synthesizer stores the combined call's selfVerdicts up-front; proposals are then deduped/rejected and appends can fail, so the junction can mutate on reviews that commit zero events). Persist failures are contained in their own try/catch with a distinct `"Registry persist failed"` scheduler_error operator event, never the outer "World review failed" catch; the pulse and the committed order survive — cache semantics, a failed write degrades restart to pre-slice behavior.

**4. D-1 compliance: no `IGoalRegistryRepository`; a structural persister (D-32).** The interface rejected by ADR-0009 D-1 remains rejected. Shape: a concrete `SqliteGoalRegistryRepository` (constructor `(db: DB)`, `SqliteMemoryRepository` shape, `type GoalSelfVerdictRow` + `rowToEntry` mapper, `Promise.resolve` wrappers, `loadSelfVerdicts` ordered by `goal_id`) in `persistence/sqlite/goal-registry-repository.ts`, plus a 2-method structural type `GoalRegistryPersister = { saveSelfVerdicts(sim, entries); loadSelfVerdicts(sim) }` defined in world-evaluator.ts (test seam + layering boundary: `world/` imports persistence types only, no sqlite impl classes), plus the entry type `GoalSelfVerdictEntry = { goalId; verdict: SelfVerdict; source: "llm" | "deterministic" }` defined once in the repo file and type-imported by world-evaluator — one definition, no cycle, no `implements` keyword (structural satisfaction). `WorldEvaluator`'s constructor gains an optional 7th param (absent ⇒ memory-mode no-op).

**5. No config knob; resume through the supported factory (D-33).** Registry persistence derives from the existing `persistence.type` — sqlite ⇒ sqlite-backed, memory ⇒ in-memory no-op. Factory selection stays the single point at `createRepositories` (simulation-config.ts), which constructs the repo in its sqlite branch; the memory branch changes nothing; the runtime repos type gains the optional `goalRegistryRepo` slot only via a local intersection type in simulation-config.ts. Resume through the supported factory: `buildConfiguredSimulation` gains `attachExisting?: boolean` (default **false** — a fixed-id config against a pre-existing row without the flag keeps today's loud sqlite PK failure, never a silent attach to stale state), forwarded to `SimulationRuntime.createSimulation`, whose `createFromConfiguredChannels` path gains a get-or-create branch: when `attachExisting` is set and `simRepo.get(simId)` finds the row, it resolves `defaultChannel` via `channelRepo.getById` (named error if missing) and skips the sim/channel/membership INSERTs that would violate the `simulations.id` PK (the `simulations` → `channels`/`memberships` cascade keeps the existing rows, so the INSERTs are redundant on resume; `delivery.createChannel` still runs per configured channel — gateway-side registration only). The branch rides the shared `simRepo.get`/`channelRepo.getById` contracts, both of which exist identically in the InMemory and Sqlite implementations, so **memory mode gets the same get-or-create restart semantics** (memory's previously-idempotent `Map.set` create now converges with sqlite at the runtime level instead of silently overwriting).

**6. Recorded in ADR-0012 as D-29..D-36 (D-34).** Each goal-layer slice owns its ADR (0009=#93, 0010=#94, 0011=#96, 0012=#97). First-free numbering from the merged tree's actual high-water mark, reconciled at write time (this status line's numbering note); the file number is the next-free (`0012`; ADR-0011 lives only on the unmerged #96 branch). If the queue state changes before merge, the status line shifts to the re-derived range and inline D-refs follow it.

**7. D-23 flip: selfVerdicts are durable in sqlite mode (D-35).** The restart-degradation-to-structural-V1 documented in ADR-0010 D-23 is **removed in sqlite mode**: the junction restores before the first review. AC-2's "resumes goals/verdicts/gap history" includes selfVerdicts (they are verdicts), and the degradation was a documented consequence, not a feature. Termination semantics are untouched (G5: the ending still gates on the world verdict only; a stored belief is a cache; the deluded achiever still re-goals and never terminates). D-23's rejected-alternative rationale — committing self-verdict events grows the event contract and visibility surface — does not apply to out-of-band persistence: the event contract stays untouched. The ADR-0010 A-2 restart-degradation consequence is scoped to memory-mode restarts (G9) and the registry A-2 test stands as pure-replay documentation.

**8. Deliberate file-I/O test deviation (D-36).** AC-2 cannot be expressed on `:memory:` — a closed `:memory:` DB cannot reopen, and the point of the restart AC is a closed-and-reopened file. One test file (`simulation/world/__tests__/goal-restart.test.ts`) deviates from the persistence suite's "no file I/O" convention: `mkdtempSync` + `buildConfiguredSimulation` with `persistence: { type: "sqlite", path }` twice against one path, `closeDatabase` between phases, `rmSync` teardown in afterEach. All other persistence tests keep `:memory:`; the deviation is confined to this file and documented here.

## Rationale

- **Junction-only over full snapshot (D-29):** replay already reconstructs five shapes byte-for-byte (proven by existing replay tests); the issue's real gap is the one junction `rebuildFromLog` cannot rebuild — selfVerdicts, which are LLM output and never committed (D-4 store contract). The smallest useful surface (ADD Simplicity Standard) is the honest gap, not the issue's letter.
- **Replay authority over DB-hydrated startup (D-30):** the issue states R-1 explicitly; DB-hydrated startup accelerates marginally on tiny logs, violates R-1, and would make the DB the authority by accident. Keeping one construction path (`new GoalRegistry(log)`) plus a keyed overlay also preserves G9 memory-mode byte-identity trivially — the memory path is the same code with the overlay empty.
- **Review-end write-through over in-review hooks (D-31):** the brief's G9 note — writes must be review-end only, never mid-review — so a failed DB write cannot corrupt the committed order; per-mutation hooks would spread ~6 call points that are not review-end; one call point after the commit keeps the "DB never leads the log" invariant textual.
- **Structural type over an interface (D-32):** D-1's rejection records interface-rejection as the norm for this aggregate; the evaluator still needs a typed dependency slot that does not import the concrete sqlite class (layering); a 2-method structural type satisfies it without resurrecting the I-interface or duplicating the entry type.
- **Derivation over a knob (D-33):** a `goalLayer.persistence` style knob would be config surface with one legal value (dead surface); always-on sqlite writes for memory runs would change behavior. The factory's existing single-selection point on `persistence.type` makes derivation free. The attach-existing branch is opt-in because resume must never be silent: a restart that forgets the flag fails loudly with the pre-slice PK error rather than binding a fresh config to stale rows.
- **D-23 flip is a designed reversal (D-35):** the ACs say "resumes goals/verdicts/gap history"; selfVerdicts are verdicts; the degradation was a documented consequence, not a feature. The flip is possible without committing self-verdict events — D-23's actual constraint — because out-of-band persistence leaves the event contract untouched.
- **One documented deviation over an unproven AC (D-36):** ACs are binding; the restart proof requires a reopenable file. Containing the exception to one test file preserves the convention's value (fast, hermetic `:memory:` suites) everywhere else.

## Rejected Alternatives

- **Full six-shape snapshot table** (the issue's "letter": sqlite backing behind the whole registry). Rejected: five of six columns written but never read at runtime — replay is the authority, so the cache is unverifiable-at-runtime surface; positional risk if it ever shortcuts ordering.
- **Persisting self-verdict events** (commit `self_verdict` events so replay restores the junction). Rejected: grows the event contract and visibility surface with no consumer — D-23's rejected alternative stands; out-of-band table writes achieve the durability without the contract cost.
- **DB-hydrated startup** (read a snapshot, skip replay). Rejected: violates R-1, makes the DB the authority by accident, positionality risk.
- **Write-through inside `runReview`** (persist mid-review, before commit). Rejected: the snapshot could lead the log on a failed commit — the committed order must win.
- **Per-mutation persistence hooks** (persist on every `record*` call). Rejected: ~6 call points, none review-end, each an ordering hazard.
- **`IGoalRegistryRepository` in `repositories.ts`** (the natural persistence-house interface). Rejected: recorded-decision reversal of D-1; the structural persister satisfies the evaluator without it.
- **Evaluator holding the concrete `SqliteGoalRegistryRepository`** (direct coupling). Rejected: world→sqlite-impl coupling; the structural type keeps `world/` importing persistence types only.
- **Duplicating the entry type in two files** (world-evaluator + repo). Rejected: drift surface; one definition in the repo file, type-imported.
- **New `goalLayer.persistence` style knob** (explicit config for registry persistence). Rejected: config surface with exactly one legal value — dead surface; derivation from `persistence.type` is free at the existing single selection point.
- **Silent always-attach on resume** (no flag; existing row ⇒ attach). Rejected: binds a fresh config to stale rows without the caller knowing; the flag keeps the failure loud (D-33).
- **`IGoalRepository` + sqlite `goal` table** (D-4's original heaviest option, revisited). Rejected: contradicted D-1's norm at the time and still does; the shipped shape keeps the interface rejected while delivering the persistence.
- **Keeping the D-23 degradation and documenting it** (test-only closure of AC-2). Rejected: AC-2 fails its natural reading — "verdicts" includes selfVerdicts; the degradation was a consequence, not a feature (D-35).
- **`:memory:`-only restart test** (preserve the no-file-I/O convention). Rejected: a closed `:memory:` DB cannot reopen, so AC-2 is unprovable on it.
- **Manual runtime re-wiring for the restart test** (hand-rolled sqlite runtime composition instead of the factory). Rejected: duplicates `buildConfiguredSimulation`; the AC is about the supported factory, so the test must drive it.

## Consequences

- **AC-1 is pinned by a parity test**: one committed log (all five event shapes via `SqliteEventRepository.append`) fed to replay-only and sqlite-restored builders; the five replayable shapes cell-by-cell equal; the junction is the exactly-one named divergence (replay leaves it empty under D-23, restore returns the saved entries); restored state equals the pre-restart registry on all six shapes.
- **AC-2 is pinned by a restart test**: two phases on one sqlite file — deterministic leg through `buildConfiguredSimulation(config, { attachExisting: true })` (goals/verdicts/gapHistory/proposals/pendingOffer equal across phases; selfVerdicts correctly not asserted on the deterministic leg — deterministic mode never writes the junction, D-19), plus a hand-wired deluded-LLM leg for the strict mid-run proof (junction populated with `claim: "reached"` while the world verdict is `not_reached` and the run is still active; after reopen + restore, the junction equals pre-restart cell-by-cell).
- **G9 holds**: memory mode constructs no persister, so the evaluator no-ops and the restore loop skips; memory-mode runs are byte-identical — proven by every memory-configured suite staying green and by attach-existing giving memory mode the same get-or-create restart semantics as sqlite (runtime-level convergence; the repo-level divergence — sqlite rejects create-on-existing, memory idempotently overwrites — stays pinned by sqlite-only contract-test rows).
- **The D-23 degradation is scoped to memory-mode restarts** (ADR-0010 consequence amended in place); the registry A-2 test stands as pure-replay documentation; goal-registry.ts itself is untouched — restore uses the existing `recordSelfVerdict` junction API.
- **Failure containment**: a failed write emits a distinct `"Registry persist failed"` operator event and the pulse continues; restart then degrades to pre-slice behavior — never data corruption, never a failed review. A resume without `attachExisting` fails loudly with the sqlite PK error (same failure as before this slice, safe direction).
- **Surface added**: one table, one repo class, two structural types, one evaluator method, one optional constructor param, one factory option + one get-or-create branch. No new dependencies (better-sqlite3 already direct), no migration framework (`CREATE TABLE IF NOT EXISTS` house style), no `packages/engine/src/goal/*` or `packages/server/src/llm/*` changes (G4, D-18).
- **ADR-0009 amendments live in place**: D-1's rejected-interface note gains a superseded marker pointing at D-32; D-4's in-memory-Map wording gains the memory-mode/accelerator status note.
