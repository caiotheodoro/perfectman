# ADR-0010: Goal-Layer LLM Slice

**Status**: Accepted (LOCKED, 2026-08-26) — rationale and rejected alternatives inline in this ADR (decisions D-17..D-23).

## Context

[ADR-0009](./0009-goal-layer-runtime-wiring.md) shipped the goal layer's runtime wiring and committed the LLM seams — sync `GoalSynthesizer` interface, `AcceptanceGate` contract, `goal_proposed` payload carrying synthesis provenance, `synthesizer.mode: "llm"`/`acceptance.mode: "agent"` as schema-valid-but-build-rejected modes — expressly as "the reversible seam for that slice". This slice (#94) implements the deferred D-13 trio: the LLM `GoalSynthesizer`, `"agent"` acceptance, and LLM self-verdicts. The three co-require each other: agent acceptance is meaningful only for LLM-framed (agent-legible) proposals, and LLM self-verdicts share the same prompt surface.

Design constraints carried into this slice: the engine stays pure and untouched (G4); the world verdict never comes from the target agent's own claim (G6); termination stays gated on the world verdict only (G2/G5); V1 deterministic behavior stays byte-identical (G9); no new dependencies (D-12); no new shared files and no new server `llm/` surface (D-15, D-18). The cost gate from the #93 implementation plan applies: the slice is a new LLM call class, so it must be interval-gated, budget-gated, capped, and honestly attributed.

## Decision

**1. The synthesizer seam becomes async (D-17).** `GoalSynthesizer.synthesize` widens to `Promise<GoalSynthesisResult[]>` — single method, shape-preserving; the deterministic impl wraps its existing output in `Promise.resolve` (byte-identical behavior); the one call site (`world-evaluator.runReview` synthesis block) awaits. The method, input, and result contracts are untouched, so D-15's "extends, never reshapes" holds on everything that crosses the seam except the return's async-ness, which is the interface's own contract to widen. Compile-forced: the deterministic impl, its tests, and the one call site are the only in-repo consumers.

**2. The goal call class consumes the transport functions directly — `LLMProvider` and `packages/server/src/llm/*` stay untouched (D-18, amended).** A new `GoalLayerLLMClient` (in `simulation/world/`) renders the shared prompt surface (`buildGoalLayerPrompt`, `purpose: "goal_synthesis"`, `templateVersion: "goal-layer-v1"`), budget-gates through the shared `llmBudget` singleton seam (`getPriority`/`canCall`/`recordUsage`, callType `"goal"`), and dispatches on the agent's **configured** `LLMConfig` exactly like the provider factory: `providerType: "mock"` → the deterministic canned in-client producer (D-19); `"ollama"` → `generateOllamaIntent`; any other → `generateOpenAiCompatibleIntent` — both in text mode (`responseFormatJson: false`), with local balanced-brace JSON salvage + `GoalLayerLLMResponseSchema.parse`. The transport functions are schema-constrained to `ModelIntentPacketJsonSchema`, so a synthesis prompt through the intent surface would yield intent-shaped JSON; text mode + local parse is the eval-`chatCompletion` second-call-class precedent. **Config routing is mandatory**: providerType, baseUrl, modelName, extraBody, apiKey all come from the simulation's actual per-agent `LLMConfig`; fabricated/hardcoded config values are forbidden. The `llm/` diff guard is a standing invariant — the intent surface and the provider stack are untouched by this slice.

**3. Mock leg and fallback honesty (D-19).** `providerType: "mock"` → a deterministic canned combined-JSON producer inside the client, routed through the same parse path as a real model, with provenance `"llm"`, model `"mock-model"`, and budget-recorded usage — so the mock leg runs and the cost gate is machine-checkable. Failure or budget-block → deterministic passthrough proposals (provenance `"deterministic"`) + `selfVerdicts: []` + operator events (`llm_failure`/`llm_budget_exceeded`, the `action-intent-step` literal shapes), and **no usage recorded**. Fallback verdicts are derived/transient and never stored as beliefs: a budget-blocked or failed interval records nothing into the registry, so a previously persisted LLM belief survives the interval (D-19 record gate at the persistence junction). Structural V1 (`synthesizeSelfVerdict`, default `"in_progress"`) remains the verdict block's stored-first fallback and is never a client product.

**4. Combined interval call (D-20).** One call per agent per interval review carries both the synthesis input (candidates) and the self-verdict input (active goals) over the shared prompt surface — the strongest cost control: worst case ≤1 call per agent per interval review, never per pulse (reviews only run on `reviewEveryPulses`) and never per goal. Inputs are capped by `maxCandidatesPerReview` and the new `maxSelfVerdictsPerReview` (default 3). The wire contract references items by id — the prompt renders each candidate and active goal with its bracketed id, the response echoes `proposalId`/`goalId`, and the client reattaches the canonical objects by id after schema validation (the engine owns the proposal set, so a model can neither invent proposal structure nor fabricate a goalId that enters the junction). Between interval reviews the registry's stored LLM self-verdict persists (belief persistence). Acceptance stays LLM-free (D-21).

**5. `"agent"` acceptance resolves from post-proposal behavior (D-21).** `AcceptanceGate.decide(proposal, rating, context?: AgentAcceptanceContext)` gains an additive third parameter; `AgentAcceptanceContext = { behaviorWindow: CommittedEvent[]; digest: AgentContextDigest }` (shared type + schema). `AgentAcceptanceGate` decides deterministically: accept iff the target agent authored ≥1 `message_sent`/`reply_sent`/`reaction_sent` in the proposal's channel within the window (SDT autonomy as engagement — a forced goal is not owned), decline otherwise; the reason string names the observed behavior or its absence. The behavior window is the log slice from the `goal_proposed` commit position to log end (ADR-0009's positional rule), filtered to the proposal's agent + channel. The auto gate ignores the context (its 2-parameter signature satisfies the widened interface). Acceptance happens at review N+1 — one full window after proposal, so the target agent perceives `goal_proposed` (D-11, unchanged) before the gate reads its behavior.

**6. Honest attribution (D-22).** `PromptPurpose` gains `"goal_synthesis"` and `LLMUsage.callType` gains `"goal"` — both additive union growth, test-pinned (`noImplicitReturns` is off, so the switches are not compile-forced; fail-closed cases are pinned by TT203 through `PromptBuilder.build` on reserved purposes — the goal surface owns its builder) and `purposeToCallType`. The cost-per-goal-call metric joins on the synthesizer provenance field; the budget tracker's callType is the operational attribution separating the goal class from cognition.

**7. LLM self-verdicts ride the registry junction (D-23).** `GoalRegistry` gains additive `recordSelfVerdict(goalId, verdict, source)` / `getSelfVerdict(goalId)` state — the world layer's per-simulation store is the one object the synthesis block and the verdict block both already share, so the junction needs no constructor/interface churn. `LLMGoalSynthesizer` stores the combined call's verdicts (source `"llm"`) and returns only proposals (the interface is untouched); the verdict block resolves `getSelfVerdict(goal.id)?.verdict ?? synthesizeSelfVerdict(...)` (stored-first, structural V1 fallback). `computeDelusionGap`/`evaluateEndCondition` are untouched (G2/G5 — an LLM claim can never short-circuit termination). `rebuildFromLog` cannot restore LLM verdicts (LLM output is never committed — D-4 store contract), so a restarted simulation degrades to structural V1 until the next interval success.

## Rationale

- **Async widen over a second interface (D-17):** an LLM impl must await a transport call, and D-15's "sync-by-design" note reads as "the wrapper owns the await" — which the wrapper does. A second async interface beside the committed one would duplicate the seam D-15 exists to keep singular; fire-and-forget queuing breaks review determinism and ordering.
- **Transport-direct over provider-surface growth (D-18):** P1 (a second `LLMProvider` method) is the largest provider-surface change — interface + three providers + mock + factory all gain an intent-unrelated method. The eval `chatCompletion` precedent proves the transport-direct pattern across the package boundary, and the server package's "only package allowed to depend on the AI SDKs" boundary is honored with zero `llm/` churn. The amended routing rule closes the loop that keeps the mock leg honest: the mock branch fires only when the simulation *configured* a mock provider.
- **Mock leg records usage (D-19):** #94-8 demands call counts be machine-checkable; a mock leg that short-circuits to the deterministic fallback records zero usage — dishonest budget accounting. Treating the mock as an LLM stand-in is the shipped `MockLLMProvider` precedent on the agent path; the narrator's "rule" provenance is for NO-endpoint fallback, which here is the deterministic path and is marked `"deterministic"` honestly. The never-stored rule means a fallback can never clobber a persisted belief with a structural `in_progress` verdict.
- **Combined call over per-goal or separate calls (D-20):** per-goal self-verdict calls amplify to n_active_goals per review; separate synthesis/verdict calls cost 2+ per agent per review; both misread "share the same prompt surface". Acceptance stays out of the LLM call because it has no prompt-contract precedent and would widen the fallback blast radius to the SDT gate.
- **Behavior-grounded acceptance over an LLM interpretation call (D-21):** D-7 reserved exactly this — "an agent-mode implementation wraps the agent's intent output in the server layer" — and the intent output is the committed message/reaction events in the guaranteed one agent turn between proposal and acceptance. It is deterministic, testable without a real LLM (#94-6), and it operationalizes "a forced goal is not owned". `adopt_goal`/`decline_goal` intent types remain rejected (LLM gaming risk; the gate covers the decision point).
- **New purpose + callType over fabrication (D-22):** reusing `"action_intent"` (the eval `chatCompletion` trick) or an existing callType would misattribute the goal call class in usage records — exactly what the cost gate exists to prevent.
- **Registry junction over client memoization or committed verdict events (D-23):** client-side memoization couples the synthesizer's lifecycle to a per-review cache; committing self-verdict events grows the event contract and visibility surface with no consumer. The registry is the world layer's state store (D-4) and both blocks already share it. Stored-first gives belief persistence between intervals (the agent's belief does not reset every review) and keeps `computeDelusionGap`/`evaluateEndCondition` untouched.

## Rejected Alternatives

- **Widening `LLMProvider` with a synthesis method (P1 of the #93 brief).** Rejected: uniform factory resolution was the only win; the cost is a second method on the interface + all three providers + mock + factory + their tests, and the intent-schema constraint makes the provider method shape awkward. The transport + budget seam is where D-12's "reuse the existing surface" is actually satisfiable for synthesis JSON.
- **A separate mock transport module / extending `MockLLMProvider` to speak synthesis.** Rejected: a third mock home for one call class, or P1-adjacent surface growth; the in-client canned producer keeps the mock leg colocated with its parse path.
- **Fire-and-forget async synthesis, callback/event-based return, or a second async interface.** Rejected: determinism/ordering breakage, no precedent, or seam duplication — respectively.
- **Per-goal self-verdict calls / separate synthesis+verdict calls / uncapped calls.** Rejected: n_active_goals amplification, 2+ calls per review, or token-unbounded prompts — the cost gate's ceiling is "~1 call per review per active proposal", and the combined call makes that the worst case, not the average.
- **LLM interpretation call for acceptance / constructor-injected per-review context / log reading inside the gate.** Rejected: a second LLM surface with the same gaming risk that killed the intent types; loss of per-proposal granularity; violation of the seam's no-I/O contract.
- **Fabricating `purpose: "action_intent"` or reusing an existing `callType`.** Rejected: usage records would misattribute the goal class as cognition, defeating the cost gate's attribution mandate.
- **Client-side verdict memoization shared between synthesizer and verdict block / committing self-verdict events / re-calling the LLM per verdict.** Rejected: lifecycle coupling, unused event-contract growth, and the amplification D-20 rejects — respectively.

## Consequences

- **The cost gate is structural, not aspirational.** One combined `"goal"`-callType LLM call per agent per interval review (never per pulse, never per goal), inputs capped (`maxCandidatesPerReview`, `maxSelfVerdictsPerReview` default 3), every wire call preceded by `llmBudget.canCall` at the agent's priority and followed by `recordUsage` (callType `"goal"`, prompt version hash, `goal-layer-v1` template). Budget-blocked/failed calls cost zero usage and degrade honestly. The mock leg records usage like a real call, so the cadence and budget proofs are machine-checkable (TT201/TT301/TT502b).
- **Provenance stays honest on every path**: `goal_proposed.payload.synthesizer` is `"llm"` only for genuine LLM outcomes (mock included per D-19/A-3) and `"deterministic"` for passthrough fallbacks; fallback success is never attributed to the model. Fallback output (`selfVerdicts: []` + passthrough proposals) is transient and never stored as a belief, so no fallback artifact masquerades as an LLM judgment downstream.
- **The V1 guarantee holds**: deterministic mode is byte-identical (the deterministic synthesizer wraps its existing output; the auto gate ignores context; nothing stores into the verdict junction). All prior suites stay green; `packages/engine/src/goal/*` and `packages/server/src/llm/*` diffs are empty (G4, D-18).
- **Synthesis↔belief-refresh coupling (A-3 fold):** the combined call runs only when `candidates.length > 0` (the evaluator's synthesis `continue` gate on candidate-less intervals), so stored LLM verdicts *persist* on candidate-less intervals (D-23 stored-first) rather than refreshing — an interval with nothing new to propose is also an interval with no LLM self-belief refresh. This is the designed belief-persistence behavior, not a staleness bug.
- **The one non-deluded path that can end a structural-in_progress arc is the plateau corner**: `plateaued` + `!nextGoalAvailable` → `end_offered` ("the story is over"), with the deluded branch (`not_reached` + self `"reached"` → `re_goal`) ordered *first* in `evaluateEndCondition` — so a deluded achiever never terminates while the world stays `not_reached`, and the arc only ends (as a narrated tragic beat) when no next goal survives the critic and the run plateaus irreconcilably. Both orderings are pinned by TT502(a) through the real scheduler path.
- **Restart degrades to structural V1 (A-2 fold) — memory-mode restarts only (D-23, amended 2026-08-26):** LLM self-verdicts are not replayable — `rebuildFromLog` leaves the junction empty (LLM output is never committed), so a memory-mode restarted simulation serves structural `in_progress` verdicts until the next interval success restores the LLM belief. Documented degradation, pinned by the registry A-2 test, which stands as pure-replay documentation. Sqlite-backed restarts restore the junction from `goal_self_verdicts` before the first review — the degradation is removed in sqlite mode; the flip is recorded as [ADR-0012](./0012-goal-registry-persistence.md) D-35.
- **Operator observability**: fallback outcomes reach the operator channel as `llm_failure`/`llm_budget_exceeded` events (the `action-intent-step` literal shapes), drained from the client → synthesizer buffer → `WorldReview.operatorEvents` → scheduler `emitOperatorEvent`. `llm_failure` is additionally in `WORLD_EVENT_TYPES` for the agent path; `llm_budget_exceeded` is operator-only. These can never feed the crystallizer input (standing isolation invariant).
- **Eval-gate tier mapping (A-7 fold):** no production prompt-surface suite exists in `packages/eval/` for judge/narrator prompts either (verified), so the goal prompt surface is served by the deterministic tiers: prompt contract tests (TT202 — render, purpose, version hash, digest caps) → mocked integration (TT201 — parse/provenance/fallback/usage; TT301 — cadence/cap/throw containment) → regression (TT503 — deterministic byte-identical) → budget checks (TT201/TT502b — call counts from the injected tracker). The real-provider half of #94-1/#94-4 and creative quality remain human/local-review evidence (T604 checklist — **not executed in this run**: no configured provider was reachable in the environment; the checklist and success criteria are in the run's change-report, and the mock/fallback legs plus the TT201/TT202/TT301 pins are the executed evidence).
- **Second-opinion seams retained**: the two sanctioned mock levers — the evaluator's injected `clientFactory` and `buildConfiguredSimulation`'s `agentRuntimeFactory` — are the seams TT502(a)/(b) drive; future slices that need observable goal integration, sqlite persistence, or intent types extend from these.
