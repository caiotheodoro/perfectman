# ADR-0009: Goal-Layer Runtime Wiring

**Status**: Accepted (LOCKED, 2026-08-25) — rationale and rejected alternatives inline in this ADR.

## Context

[ADR-0008](./0008-world-goal-layer.md) locked the goal layer's semantics — two-verdict independence, never-seeded crystallization, ending = offered + world-verified + earned — but deferred every runtime integration: pulse-loop hook, lifecycle stop path, `goalLayer` config surface, LLM seams, observability-stream emission. This slice (#93) ships the runtime wiring: an end-of-pulse world review, a reason-carrying termination path, a config-file section, and the deterministic V1 of the synthesis/acceptance pipeline.

Scope changed during planning (Step-2 revision): the acceptance path (does the sim end) depends on whether proposals are agent-legible, so the **LLM goal-synthesis seam was committed up-front** — shared contracts, config slots, server seam interfaces, call sites — while its *implementation* stays deferred. What remains deferred as one future slice (D-13): the real LLM synthesizer, `"agent"` acceptance wiring, and LLM self-verdicts. They co-require each other: agent acceptance is meaningful only for LLM-framed (agent-legible) proposals, and LLM self-verdicts share the same prompt surface.

The engine layer stays pure and untouched (G4) — only index type re-exports close the server's signature gap (D-2). All decisions below are LOCKED and recorded in this ADR; the rationale lives inline here.

## Decision

**1. World-layer subsystem and the pulse hook (D-1, D-5).** A new `packages/server/src/simulation/world/` subsystem owns the runtime goal machinery: `GoalRegistry` (per-simulation in-memory Map state, `RateLimitGate` pattern) — **D-4 status, amended 2026-08-26: the Map + replay store is now the MEMORY-mode path (G9); sqlite mode backs only the non-replayable self-verdict junction, replay stays the authority and the DB is a cache overlay in both modes ([ADR-0012](./0012-goal-registry-persistence.md) D-29/D-30)** — and `WorldEvaluator` (the server-side orchestration that consumes the six pure engine functions). The scheduler runs the review at end-of-pulse, **after the agent loop**, in the stagnation block's slot, on `pulseIndex % reviewEveryPulses === 0` (pulse 0 exempt). Review events commit only through the scheduler's `appendAndProject` — the single-writer invariant is untouched; a throwing review degrades to an operator `scheduler_error` and the pulse survives with its event counts.

**2. Crystallization input isolation (standing invariant).** The evaluator feeds the crystallizer only the agent's **organic signal history**: the six goal-layer event types plus the agent-blocked system diagnostics (`stagnation_detected`, `operator_warning`, `llm_failure`, `private_motive_summary` — mirrored from the engine's `AGENT_BLOCKED_TYPES`) are excluded from the crystallizer input. Without the filter the layer proposes goals off its own event trail — `goal_proposed`/`delusion_gap_sampled` payloads carry exact `agentId` strings (affiliation trigger) and empty-visibility `world_verdict` events are witnessed by all (legacy trigger) — a defect observed as a spurious goal's plateau ending a run that must never terminate. Verdict/gap derivation still reads the full log; organic triggers (blocks → resolve, own outbound messages → affiliation, witnessed high-salience other-agent events → legacy) are unchanged. Two further correctness invariants from the review cycle: snapshot windows are **positional** (log append order, never event `createdAt` vs sim clock), and offer delivery is **derived from the committed log** (an `ending_offered` event present ⇒ already delivered), so a failed creation commit re-delivers on the next review instead of losing the offer.

**3. Termination gate (D-6, D-14).** `PulseSchedulerConfig.onEndOffered(offer, pulseIndex)` — a stepResolver-style testability seam — is wired by `SimulationRuntime` to `stop(simulationId, { endReason: "goal_end_offered", endingOffer })`. Optional `endReason`/`endingOffer` thread through `SimulationLifecycle.stop` and `SimulationManager.stop` into the `simulation_stopped` payload via spread conditionals; the CLI SIGINT path passes no options and its payload is byte-identical (`{ simulationId }` only). The registry holds at most one pending offer; `goalLayer.ending.offerAcceptPulses` (default 0 = immediate) gates delivery. Termination gates on the world verdict only; the deluded achiever re-goals and never terminates (G5, unchanged from 0008).

**4. Config surface (D-3).** A `goalLayer` section in the simulation config file — shared zod schema (`goal-layer-config.{types,schema}.ts`, judge-section precedent), all fields optional, parsed next to the judge block, carried on `SimulationAppConfig`. Per-agent `DelusionWeights` keyed by agentId inside the section, defaulting to the engine's `DEFAULT_DELUSION_WEIGHTS`. Subsections: `synthesizer: { mode: "deterministic"|"llm", intervalPulses, maxCandidatesPerReview }` and `acceptance: { mode: "auto"|"agent" }`. The unwired modes are **schema-valid** (contract-defined, so future configs don't break) but rejected deterministically at **build time** by `resolveGoalLayerConfig` when `goalLayer.enabled` — loud failure beats silent degradation into deterministic behavior. `goalLayer` absent or disabled ⇒ zero construction, byte-identical runs.

**5. Synthesizer and acceptance seams, committed up-front (D-7, D-15, D-16).** Shared contracts in the scaffold's `goal.types.ts`/`goal.schema.ts`: `GoalSynthesizerInput` (crystallizer candidates + an intentionally small deterministic agent-context digest: persona id, capped recent memories, capped private-motive summaries), `GoalSynthesisResult` (enriched proposal, `narrativeFraming`, `confidence` 0..1, synthesizer provenance `"deterministic"|"llm"`), `SynthesizerConfig`, `GoalAcceptanceDecision`, `AcceptanceMode`. Server seams mirror the LLM layering precedent (`LLMProvider` + factory + mock fallback; narrator provenance discriminant): `GoalSynthesizer` interface — one synchronous method, no I/O inside, a future LLM implementation wraps the provider call in the server layer — + `DeterministicGoalSynthesizer` (verbatim passthrough, framing = target description, confidence 1) + `createGoalSynthesizer` factory (single resolution site; throws on `"llm"` naming the deferred slice); `AcceptanceGate` (contract-shaped for both auto and agent decisions) + `AutoAcceptanceGate` (accept iff the critic recommends; reason from rating reasons) + `createAcceptanceGate` (throws on `"agent"`). Acceptance happens at review N+1 — one full window after proposal, so the target agent perceives `goal_proposed` before the goal activates (D-11). `goal_proposed` carries the synthesis result — `goalId`, enriched proposal, framing, confidence, provenance — so agent-legibility is part of the committed event contract and the LLM slice grows into a payload shape that already exists (D-16). Synthesis is interval-gated (`intervalPulses`, default 1 — the LLM-mode cost gate) and candidate-capped (`maxCandidatesPerReview`).

**6. Divergence seam V1 (D-8).** Structural proxies only: `divergenceFromLog` = 1 − exposure ratio (fraction of canonical events the visibility layer shows the agent); `SelfVerdict` synthesized deterministically (default claim `"in_progress"`, felt signal from mood). LLM self-verdicts join the deferred LLM slice.

**7. `simulation_stopped` reasons reach gateways through the stop callback, not a stream event (D-24; LOCKED 2026-08-26).** `IDeliveryGateway.onSimulationStopped` widens to `onSimulationStopped(simulationId, endReason?, endingOffer?)` — optional params, so the five implementers and the test doubles compile unchanged. Both stop paths (the runtime goal-end path, with `opts` already in scope; the manager path, with the params already in hand) fire the callback and hold the payload, so each passes it through; composite/mock/stdout fan the two args out, the discord stopped-message appends reason and epilogue when present (the no-args output stays byte-identical), and the html-snapshot gateway captures them into the artifact replay. The flush callback remains the single stop signal (ADR-0005/0006 flush semantics untouched), which completes the D-6 "flows to every consumer" promise — previously false for gateways, since both stop paths bypass `appendAndProject` and receivers never saw the committed event. Rejected: a `simulation_stopped` operator event — both stop paths bypass the scheduler's append-and-project, so emission would need manual emits at two sites (drift risk), receivers would reconcile two stop signals (stream event + flush callback), and lifecycle machinery would move into the observability channel.

**8. `goal_declined` is the sixth goal-layer operator type (D-25; LOCKED 2026-08-26).** The declined path is a committed event with a live emission site — the review N+1 acceptance loop declines a proposal when the critic does not recommend — so a stream without it would leave declined arcs stuck at "proposed" in receiver state, an artifact-parity violation on reachable deterministic arcs. Same additive contract as the five event types, at ~3 lines plus a test row; the producer guard covers it automatically. Rejected: the issue's strict five-name list — a smaller surface with a known panel-state defect on the declined branch.

**9. Panel state is run-level, replay exposure optional, payloads lossless (D-26; LOCKED 2026-08-26).** The html-snapshot receiver keeps a per-simulation `Map<goalId, GoalPanel>` (the channels-map precedent): `world_verdict` replaces the latest verdict (state-only), `delusion_gap_sampled` appends one sample, and proposal/acceptance/decline/ending events update status and fields. The panel is exposed as an **optional** `SimulationReplay.goals` so the e2e recorder — which also constructs `SimulationReplay` — compiles untouched; per-frame goal maps would duplicate state until the next goal event (frames already preserve the operator-event stream), and a mandatory field would force a recorder that does not consume goal events. Operator `data` is the whole committed payload (`event.payload satisfies EventPayload`, the `llm_failure` projection precedent): lossless by construction, with no typed payload interfaces for the new types — projection-mapped operator events carry loose payloads today, so typed interfaces would be unreferenced declarations (the typed interfaces in shared/operator.types.ts exist only for direct-emit sites). Rejected: per-frame goal maps rebuilt in `toReplay` (duplication, no consumer) and six typed payload interfaces (no emission site constructs them).

## Rationale

- **Subsystem placement (D-1):** the brief's structural precedent (RateLimitGate state pattern + stagnation-chain orchestration) and G4 (engine-snapshot purity) force world-layer state off `AgentState` and out of `executePulse`; a separate evaluator keeps the scheduler at its current size and gives the six pure engine functions exactly one server-side consumer.
- **Runtime stays the only stopper (D-6):** the scheduler has no path back to the runtime today; routing the offer through `SimulationRuntime.stop` keeps the `active` map, `onSimulationStopped` delivery, and lifecycle idempotency correct in one place, and the reason flows to every consumer (log, gateways, observers) in a single contract change — while the no-opts SIGINT path proves backwards compatibility.
- **Judge-section precedent for config (D-3):** the shared schema-owner/server-parse pattern already shipped for `judge`; all-optional fields make existing configs byte-identical; per-agent weights cannot live in personas (`rejectSimulationCalibrationFields` forbids them there).
- **Two-legacy argument for acceptance (D-7):** neither mode is a permanent architectural commitment — "auto" is not a forever-default and "agent" is not a promised behavior. Auto-acceptance is defensible for deterministic recovered-striving proposals (recognition-by-behavior: the world recognizes the agent's own pattern); agent acceptance is meaningful only once the synthesizer speaks the agent's language (an LLM-framed, persona-actionable proposal = the SDT autonomy path; a forced goal is not owned). The gate interface is the reversible seam: switching modes later is a config + factory change, not a contract change.
- **Seam plan committed now, implementation later (D-15):** re-planning the seam after implementers froze the proposal/event shapes would churn shared types, config, and payloads already in use; the acceptance path (D-7) is otherwise unverifiable until the LLM slice. The sync no-I/O interface mirrors `LLMProvider` — the wire stays out of callers; the deterministic fallback and the `narrator: "llm"|"rule"` provenance discriminant are the shipped precedents for provenance-carrying results.
- **Payload carries the framing (D-16):** the target agent perceives `narrativeFraming` through the existing visibility pipeline (`visibleToAgents: [agentId]`); without it the acceptance path loses — or must re-derive — exactly the artifact the LLM slice produces.
- **Build rejection of unwired modes (D-3):** schema-validity commits the contract so future configs don't break; build-time rejection guarantees an unwired mode can never silently pass as deterministic.
- **N+1 acceptance timing (D-11):** same-review promotion collapses `goal_proposed`/`goal_accepted` into one indistinguishable step and makes the registry's proposed-status state machine dead code; the agent must perceive the proposal on its next turn before the goal activates (narrative seam).
- **Pending-offer window (D-14):** the brief's termination-gate option A includes the window as registry-held state; the single-offer invariant guards the double-offer path surfaced by `EndConditionResult` (a deluded-reached arc can later hit the plateau branch).
- **Structural V1 divergence (D-8):** R2's spectrum model makes a structural proxy acceptable for V1; determinism is a hard gate (G9), and there is no existing self-claim machinery anywhere to reuse — the producer is flagged as net-new.

## Rejected Alternatives

- **Registry state folded into the scheduler / engine snapshot (D-1).** Rejected: grows `executePulse` by a ~250-line subsystem, entangles pulse mechanics with goal transitions, and contaminates engine-snapshot purity (G4). A separate `IGoalRepository` interface was also rejected — `IMemoryRepository` exists unwired; that is the codebase norm. **This interface note is superseded for persistence by [ADR-0012](./0012-goal-registry-persistence.md) D-32 (2026-08-26): the sqlite backing ships as a concrete repository satisfying a structural persister type — still no interface.**
- **Scheduler self-stop (D-6).** Rejected: duplicates lifecycle logic and leaks the runtime's `active` map (missing `active.delete` + `onSimulationStopped` delivery).
- **Config on `SimulationSettings.goalLayer` or a new `AgentConfig` field, or keeping `autoAcceptRated` alongside `acceptance.mode` (D-3).** Rejected: the engine-adjacent strict settings object must not carry feature config; personas are packaged constants; two config ways to say the same thing is a contradiction surface.
- **Acceptance fixed as auto forever / shipping agent mode now (D-7).** Rejected: the fixed-as-auto wording forecloses the autonomy path without a committed contract; agent mode's meaningful input (LLM-framed proposals) does not exist yet. New `adopt_goal`/`decline_goal` intent types also rejected — days of surface, LLM gaming risk; the gate interface covers the same decision point.
- **Deferring the seam plan together with its implementation (D-15).** Rejected: the acceptance path would be unverifiable until the LLM slice, and hardening contracts later churns committed event/config shapes. An abstract async synthesizer contract was rejected too — the interface stays sync so the LLM wrapper owns the await, exactly like the provider surface.
- **LLM narrative scorer for divergence (D-8).** Rejected: breaks determinism and cost discipline; explicitly deferred by the spec.
- **Same-review promotion (D-11), immediate-stop only (D-14), new dependencies (D-12), server-local re-declaration of engine types (D-2).** Rejected: each collapses a designed transition or duplicates ownership; the existing stack (zod, engine, shared) fully covers the slice and the deferred LLM implementation reuses the existing provider + budget surface.
- **Growing `PulseResult` / adding emotion impulse rows for the six event types (D-9, D-10).** Rejected: unused additive surface every pulse test must be re-checked against, and `constants.test.ts` hard-asserts the impulse table length — goal events are system-authored and must not contaminate the two-verdict independence (G2).

## Consequences

- Runs can now end by earned offer through the runtime: the committed sequence `goal_proposed → goal_accepted → world_verdict → delusion_gap_sampled → ending_offered → simulation_stopped` (payload `endReason: "goal_end_offered"` + epilogue) is proven by a deterministic integration test, with no `active`-map leak after stop.
- Default-off and additive: `goalLayer` absent or disabled ⇒ byte-identical runs and zero construction; the full server (601 tests), shared (117), and engine (302) suites stay green; the no-opts SIGINT stop payload is byte-identical.
- V1 is fully deterministic — zero LLM calls. The deferred LLM slice (real synthesizer + `"agent"` acceptance + LLM self-verdicts, one deployment) grows into committed contracts, config slots, and payload shapes, and is blocked loudly at build until it lands.
- Crystallization input isolation is a standing invariant of the subsystem: the world layer can never propose goals off its own event trail; system-authored diagnostics and the six goal-layer types are excluded at the evaluator's single call site.
- Executed from 0008's deferred list: pulse-loop wiring, `simulation_stopped` end-reason emission, `goalLayer` config surface, and the LLM-seam plan. Still deferred: sqlite registry persistence, `adopt_goal`/`decline_goal` intent types, the LLM implementations, and the engine test/docs packs.
